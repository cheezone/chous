# chous 宣言

> 能跑，但还是臭。

chous 检查一个仓库的品味：它整不整洁，有没有秩序，用的东西烂没烂。它不检查正确性、安全、性能、功能和测试。有 bug 的仓库可以很优雅，功能完全正确的仓库也可以很丑。

审美只有一套，不能配置、不能关闭。chous 有权指出丑陋，你有权保留丑陋。

## 四种品味

### 现代

- 停止维护的技术就是臭的，从停止维护那天起，没有宽限期。它还能跑，和臭不臭无关。
- 作者宣布废弃的、作者故意破坏的、官方说已过时的，都是臭的。
- 健康的旧技术不臭。不追新，不搞技术鄙视链：慢、老、不时髦都不算臭，没人宣布的「没人维护」也不算。

### 秩序

- 同一个东西只用一个名字：`test/` 和 `tests/`、`plugin/` 和 `plugins/`、只差大小写的两个文件，都是臭的。
- 同一个目录只用一种起名方式。用 kebab、snake 还是 camel 由你定，只要一致。
- 根目录是入口，不是资料堆。除了有位置约定的文件（README、LICENSE、CONTRIBUTING 这类，以及 AGENTS.md、CLAUDE.md），根目录最多再放 3 份文档。这是立场，不是测量出来的数字。
- 一种职责只用一个工具：两个包管理器、两个格式化工具、两套 git hooks、两个发版工具并存，都是臭的。
- 同一个事实只说一遍：一个依赖跨两个大版本、两份内容一模一样的说明文件、两处声明同一份 workspace 列表，都是臭的。

### 约定

- 框架写明了约定，就照约定来。框架根本不会读的文件（Next.js 根目录有 `app/` 时的 `src/app`、Nuxt 4 放在 `app/` 外面的 `pages/`）是死代码，看着像活的，最臭。
- 约定以官方原文为准，每一条都附有来源。

### 洁净

- 不提交构建产物、系统垃圾、日志、个人配置。
- 不保留工作留下的东西：手动备份、一次性脚本、某一次工作的记录。历史交给版本控制，过程交给 PR。
- 源码树里不放构建出来的二进制。构建出来的东西属于 Releases。

## chous 知道什么

chous 只说它确定的事实，所以每条结果分两种：

- **臭味**：事实明确，而且违反上面的品味，不需要再判断。例如「Node 16 已于 2023-09-11 停止维护」「`package.json.bak` 是旁边那个 `package.json` 的拷贝」「根目录有 9 份文档」。
- **待审视**：事实明确，但它的含义需要 chous 没有的上下文。例如一个名字像工作日志的文件，chous 知道它叫什么，不知道它写的是什么。交给你或你的 agent 判断。

这两种不是严重程度，而是 chous 知道多少。没有错误、警告、提示之分，也没有分数。臭味会让 chous 以非零状态退出，待审视的不会。

**事实错了才是误报，审美不同不是。** 说 Node 16 已经停止维护而其实没有，是误报；说它臭而你觉得还能用，不是。知名项目也会妥协，chous 不为任何项目开例外。

## chous 不做什么

- 不惩罚缺失：没有测试、没有 CI、没有 TypeScript、没有许可证，都不报。chous 只看你已经做了的选择。
- 不靠文件名定性：名字只能让一个文件进入「待审视」，不能让它变成「臭味」。
- 不为迁就某个项目加豁免。只维护两种名单：官方的位置约定，和已经发生、可以核实的历史事实（停止维护的日期、作者宣布的废弃）。
- 不联网，不调用 AI，不需要任何 key。

## 交给 agent 的部分

有些品味需要读懂代码才能判断，这些不写进 chous 的规则，由 agent 按这份宣言来判断：

- 注释掉的旧实现：历史交给版本控制。
- 已经没有调用方的兼容层、适配层、转发层。
- 重复的实现、没有必要的抽象。
- 提交进来的生成代码，旁边却没有生成它的方法。
- 一个文件到底还有没有用：chous 只能说「它的名字像一份工作日志」，agent 能读完它，再决定它该放进 docs/、写进 PR，还是删掉。
- 一个依赖能不能用平台自带的能力替代：chous 知道平台自带了什么，agent 知道这个项目用了它的哪些部分。

`chous manifesto` 会输出这份宣言，agent 可以先读它，再审视整个仓库，而不只是处理 chous 列出的结果。

## 附录：每条规则知道什么、主张什么

| 规则 | chous 知道的事实 | chous 的主张 | 品味 | 结果 |
|---|---|---|---|---|
| 停止维护的运行时、框架 | 版本文件、Dockerfile、依赖里写的版本，以及官方公布的停止维护日期 | 停止维护的就是臭的 | 现代 | 臭味 |
| 作者宣布废弃、故意破坏的依赖 | 依赖名和作者的公开声明 | 不在废弃的东西上继续建造 | 现代 | 臭味 |
| 死掉的工具留下的配置（`.bowerrc`、`tslint.json`）、旧格式（`.cursorrules`、`bun.lockb`、Next.js 16 的 `middleware.ts`） | 文件存在，作者说过它已过时 | 换成作者推荐的写法 | 现代 | 臭味 |
| 平台已自带同类能力的依赖 | 平台从哪个版本开始自带 | 能不能完全替代，要看项目怎么用它 | 现代 | 待审视 |
| 只差大小写、单复数、同义的目录 | 两个名字同时存在 | 一个东西一个名字 | 秩序 | 臭味 |
| 同一目录命名风格混用 | 每个文件名的风格 | 同一目录一种风格 | 秩序 | 臭味 |
| 根目录文档太多 | 根目录有几份没有位置约定的文档 | 根目录是入口 | 秩序 | 臭味 |
| 同一职责的工具并存 | 两个工具的配置、lockfile 或脚本都在 | 一种职责一个工具 | 秩序 | 臭味 |
| monorepo 里依赖跨大版本、嵌套 lockfile、重复声明 | 版本号和文件位置 | 同一个事实只说一遍 | 秩序 | 臭味 |
| `CLAUDE.md` 和 `AGENTS.md` 一模一样 | 两份文件内容完全相同 | 留一份，另一份软链接或 `@AGENTS.md` | 秩序 | 臭味 |
| 框架不读的文件、框架找不到的大写目录 | 框架文档写明的规则 | 照框架的约定来 | 约定 | 臭味 |
| 构建产物 | 构建工具写下的标记文件，或者有构建脚本 | 不提交构建产物 | 洁净 | 臭味 |
| 系统垃圾 | 文件内容是操作系统写的（`.DS_Store` 的 `Bud1`） | 不提交系统垃圾 | 洁净 | 臭味 |
| 日志、`.env*.local`、个人 IDE 和 agent 配置 | 文件名，以及工具文档里「不要提交」的原话 | 不提交个人和本地的东西 | 洁净 | 臭味 |
| 旁边有原件的备份（`package.json.bak`） | 原件就在旁边 | git 已经保留了旧版本 | 洁净 | 臭味 |
| 构建出来的二进制（`.exe`、`.apk`、`.dmg`……） | 文件格式 | 构建出来的东西属于 Releases | 洁净 | 臭味 |
| 名字像工作日志的文档 | 文件名 | 记录某一次工作的，应该写进 PR | 洁净 | 待审视 |
| 名字像一次性脚本、也没被提到的脚本 | 文件名，以及没有任何文件提到它 | 用完就删 | 洁净 | 待审视 |
| 找不到原件的备份 | 文件名 | 可能是备份，也可能不是 | 洁净 | 待审视 |

测试夹具（`fixtures/`、`testdata/`、`__snapshots__/`）是数据，`vendor/` 是别人的代码，这两类不检查。`tests/`、`examples/`、`playground/` 是你自己的代码，照常检查。
