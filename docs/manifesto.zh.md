# chous 宣言

> 能跑，但还是臭。

chous 检查一个仓库的品味：它整不整洁，有没有秩序，用的东西烂没烂。它不检查正确性、安全、性能、功能和测试。有 bug 的仓库可以很优雅，功能完全正确的仓库也可以很丑。

审美只有一套，不能配置、不能关闭。chous 有权指出丑陋，你有权保留丑陋。

## 四种品味

### 现代

- 停止维护的技术就是臭的，从停止维护那天起，没有宽限期。它还能跑，和臭不臭无关。
- 作者宣布废弃的、作者故意破坏的、作者自己称为遗留（legacy）或维护模式的，都是臭的：作者在 npm 上标记废弃的包、进入维护模式的 Vue CLI、Cargo 废弃的 `authors` 字段。
- 健康的旧技术不臭。不追新，不搞技术鄙视链：慢、老、不时髦都不算臭，没人宣布的「没人维护」也不算。

### 秩序

- 同一个东西只用一个名字。chous 能认出的只有写法：只差大小写或 Unicode 形式的两个名字。`test/` 和 `tests/` 是不是同一个东西，要读懂词义，交给 agent。
- 同一个目录只用一种起名方式。语言没有规定的，用 kebab、snake 还是 camel 由你定，只要一致。
- 根目录是入口，不是资料堆。除了有位置约定的文件（README、LICENSE、CONTRIBUTING 这类，以及 AGENTS.md、CLAUDE.md），根目录最多再放 3 份文档。这是立场，不是测量出来的数字。
- 隐藏文件和普通文件同等对待：放在 `.` 开头的目录里，不会让一样东西变得不臭。
- 配置尽量集中，但不打破职责边界：一个工具的配置放一处，不同的工具各自一份。
- 不平铺，不堆积。一个目录里堆着几百个文件、一个文件塞进所有职责，都是没有组织。chous 指出超过立场值的（见「chous 不做什么」），是不是职责过度集中，交给 agent 判断。
- 用哪些工具、用几个，由你决定；chous 不按职责数工具。
- 同一个事实只说一遍：一个依赖跨两个大版本、两份内容不一致的 workspace 列表，都是臭的；内容完全相同的文件，要么只留一份，要么说得出为什么要有多份。
- 依赖多少不是臭味。

### 约定

- 语言规定了名字怎么写的，照规定来：Python 模块全小写，Go 的包名是一个小写单词，Dart 文件用 lowercase_with_underscores。官方说「没有定论」的（Rust 的 crate 名）或「不做规定」的，chous 也不规定。框架的约定会随版本变，chous 不收。
- 允许兼容多个运行时，允许必要的重复：`package.json` 的 `workspaces` 和 `pnpm-workspace.yaml` 内容一致时，是为了让 npm、Yarn、Bun 也能读，不算臭；内容不一致才臭。
- 约定以官方原文为准，每一条都附有来源。
- chous 只收几年不维护也成立的约定。具体工具的配置字段、读取顺序、默认上限、某个版本起的行为都会变，不收：工具自己会诊断，agent 也能读到最新的文档。

### 洁净

- 不提交构建产物、系统垃圾、个人配置。
- 不保留工作留下的东西：手动备份、一次性脚本、某一次工作的记录。历史交给版本控制，过程交给 PR。
- 源码树里不放安装包。构建出来交给用户的东西，属于 Releases。
- 允许为未来扩展先建好空壳文件。空的不等于没用。

## chous 知道什么

chous 只说它确定的事实，所以每条结果分两种：

- **臭味**：事实明确，而且违反上面的品味，不需要再判断。例如「Node 16 已于 2023-09-11 停止维护」「`dist/` 被 .gitignore 忽略，却仍被提交」「根目录有 9 份文档」。
- **待审视**：事实明确，但它的含义需要 chous 没有的上下文。例如一个可执行文件，chous 从文件头认得出它的格式，不知道它是构建产物还是构建要读的输入。交给你或你的 agent 判断。

这两种不是严重程度，而是 chous 知道多少。没有错误、警告、提示之分，也没有分数。臭味会让 chous 以非零状态退出，待审视的不会。

**事实错了才是误报，审美不同不是。** 说 Node 16 已经停止维护而其实没有，是误报；说它臭而你觉得还能用，不是。知名项目也会妥协，chous 不为任何项目开例外。

chous 怎样确认事实：

- 停止维护的日期只收官方数据里写着的版本。表里没有的版本不报，也从不推断日期。
- 版本只取实际运行的环境：`.nvmrc`、`.node-version`、`.python-version`、`.tool-versions`、项目里任何一个 Dockerfile 的 `FROM`（经过任何镜像仓库，`ARG` 展开后）、GitHub workflow 任务安装的版本或运行它的容器、dev container 的镜像和 features、`volta.node`、框架依赖。CI 矩阵测试的是兼容承诺，和 `engines` 一样，不读。Node 的代号（`lts/gallium`）按官方时间表换算成版本。`engines.node` 是兼容承诺，不是运行环境；只有它声明的范围全部已停止维护时才报，例如 `^16`。
- 文件的身份靠内容确认，不靠名字：`.DS_Store` 开头的 `Bud1`、Android 写进 `local.properties` 的「绝不能提交」、安装包和可执行文件的文件头、构建工具写下的标记文件。
- 引用别人的话，原话和它的工具放在一起（`src/facts/tools/`），只在收录时核对一次：官方文档改个措辞不是新闻。停止维护的日期由程序从官方数据写入，每周比对一次。

## chous 不做什么

- 不惩罚缺失：没有测试、没有 CI、没有 TypeScript、没有许可证，都不报。chous 只看你已经做了的选择。
- 行数、体积、文件数量不定性。超过立场值的只进入「待审视」：源文件超过 1000 行、一个目录平铺 50 个以上源文件、根目录超过 30 个文件、agent 指令文件超过 300 行，以及内容完全相同的文件。是否职责过度集中，由 agent 判断，**不要机械拆分**。这些数是立场，不是测量出的好坏：在 85 个真实仓库里，它们只圈出分布的尾部。知名项目也不是审美标准。GitHub 拒收的文件（50 MiB 起警告、100 MiB 拒收）是平台的硬限制，直接是臭味。
- 不读名字里的词：`FIXES_SUMMARY.md`、`index.ts.bak`、`报告-最终版.md`、`백업.ts`，对 chous 来说什么都没说。换一种语言就要再猜一遍的规则，不是事实。只有工具或操作系统规定的确切名字算数，而且要有内容佐证。
- 不为迁就某个项目加豁免。只维护两种名单：已经发生、可以核实的历史事实（停止维护的日期、作者宣布的废弃），和几十年不变的少量约定（语言的命名规定、工具规定的确切文件名）。
- 不收易变的生态知识：除了停止维护和明确的废弃，需要知道具体软件的名字和版本才成立的规则，一概不收。chous 的价值在通用检测，从没被适配过的语言也能受益；支持多少工具不是进展。
- 不联网，不调用 AI，不需要任何 key。

## 交给 agent 的部分

有些品味需要读懂代码才能判断，这些不写进 chous 的规则，由 agent 按这份宣言来判断：

- chous 列出的长文件是不是承担了太多职责。行数只是让人去看的理由，编译器的代码生成本来就大。**不要为了把行数压下来而机械地拆分文件**：一个职责一个文件，而不是一个行数一个文件。
- chous 列出的平铺目录，是不是应该按职责分组。
- chous 列出的重复文件，哪些是必要的（每种屏幕密度一份的图标），哪些是复制粘贴。
- 具体工具的配置是不是过时、放错了位置、被另一份覆盖：读工具最新的文档，或者运行它自己的诊断。
- 多种语言混用：一个职责用了两种语言实现，或者为了一点点功能引入一门新语言。
- 注释掉的旧实现：历史交给版本控制。
- 已经没有调用方的兼容层、适配层、转发层。
- 重复的实现、没有必要的抽象。
- 提交进来的生成代码，旁边却没有生成它的方法。
- 源码和文档里长期积累的派工记录、任务汇报、交付记录、按版本堆积的发布说明：事情做完了，来龙去脉在 PR 和 CHANGELOG 里，仓库里不必再留一份。agent 能读完，再决定哪些还要留。
- 一个文件到底还有没有用：工作日志、手动备份、一次性脚本、`plugin/` 和 `plugins/` 是不是一个东西。chous 不读名字里的词；agent 能读完它们，再决定该放进 docs/、写进 PR，还是删掉。

`chous manifesto` 会输出这份宣言，`chous --json` 会以结构化数据输出所有结果。agent 可以先读宣言，再结合结果审视整个仓库，而不只是处理 chous 列出的那几条。

## 附录：每条规则知道什么、主张什么

每个工具具体说了什么、chous 查哪些文件，见 [chous 知道什么](facts.zh.md)（由注册表生成）。下表是规则的种类。

| 规则 | chous 知道的事实 | chous 的主张 | 品味 | 结果 |
|---|---|---|---|---|
| 停止维护的运行时、框架 | 实际运行的版本，以及官方数据里的停止维护日期；官方只说「不再支持」、没给日期的（Angular），照原话报 | 停止维护的就是臭的 | 现代 | 臭味 |
| `engines.node` 只允许已停止维护的版本 | 声明的范围，以及其中每个版本的停止维护日期 | 不要只承诺支持已经死掉的版本 | 现代 | 臭味 |
| 作者宣布废弃、称为遗留、故意破坏的依赖 | 依赖名，以及作者的公开原话：npm 的 deprecated 字段（安装时由 pnpm、npm 原样记进 lockfile，chous 直接读，只报 package.json 里直接写的依赖）、README、安全公告 | 不在废弃的东西上继续建造 | 现代 | 臭味 |
| 工具宣布废弃的清单字段（Cargo 的 `authors`） | 字段，以及工具文档的原话 | 换成工具推荐的写法 | 现代 | 臭味 |
| 只差大小写或 Unicode 写法的名字 | 两个名字同时存在 | 一个东西一个名字 | 秩序 | 臭味 |
| 同一目录命名风格混用 | 每个文件名的风格 | 同一目录一种风格 | 秩序 | 臭味 |
| 根目录文档太多 | 根目录有几份没有位置约定的文档 | 根目录是入口 | 秩序 | 臭味 |
| monorepo 里一个依赖跨大版本、嵌套 lockfile、两份不一致的 workspace 列表 | 版本号、文件位置、两份列表的内容 | 同一个事实只说一遍 | 秩序 | 臭味 |
| 源文件超过 1000 行（不计生成的、压缩的、别人的） | 行数 | 是否职责过多由 agent 判断，不机械拆分 | 秩序 | 待审视 |
| 一个目录平铺 50 个以上源文件 | 文件数 | 是否该按职责分组由 agent 判断 | 秩序 | 待审视 |
| 根目录超过 30 个文件 | 文件数 | 根目录是入口 | 秩序 | 待审视 |
| 内容完全相同的文件（4 KiB 以上；agent 指令文件不论大小） | 字节完全相同；同一个文件经软链接到达的只算一次 | 只留一份，或说得出为什么要有多份 | 秩序 | 待审视 |
| agent 指令文件（AGENTS.md、CLAUDE.md、GEMINI.md、Copilot 指令）超过 300 行 | 行数 | 只留每次都用得上的 | 秩序 | 待审视 |
| 不符合语言命名规定的名字（文件名、目录名，或文件里声明的包名） | 名字，以及语言风格指南的原话 | 照语言的规定起名 | 约定 | 臭味 |
| 构建产物、缓存、虚拟环境，不管目录叫什么 | 工具写下的标记文件（`CACHEDIR.TAG`、`pyvenv.cfg`、`CMakeCache.txt`、`.tsbuildinfo`），或者有构建脚本 | 不提交构建产物 | 洁净 | 臭味 |
| 系统垃圾、崩溃转储（ELF core 文件）、`local.properties` | 文件内容是操作系统或 Android Studio 写的 | 不提交系统垃圾和本机配置 | 洁净 | 臭味 |
| 工具自己说不要提交的文件（`.env*.local`、`.idea/workspace.xml`） | 文件名，以及工具文档里「不要提交」的原话 | 不提交个人和本地的东西 | 洁净 | 臭味 |
| 被 .gitignore 忽略却仍被提交的文件（空的占位文件和目录自己的 .gitignore 除外） | git 索引和 .gitignore 两处说法相反 | 要么取消跟踪，要么用 `!` 写明例外 | 洁净 | 臭味 |
| 50 MiB 以上的文件 | 文件大小；GitHub 50 MiB 起警告、100 MiB 拒收 | 改用 Git LFS 或 Releases | 洁净 | 臭味 |
| 安装包（`.apk`、`.ipa`、`.msi`、`.deb`、`.dmg`……） | 文件签名确认了格式 | 交给用户的东西属于 Releases | 洁净 | 臭味 |
| 可执行文件和库（`.exe`、`.dll`、`.so`、`.dylib`，以及没有扩展名的 ELF、Mach-O） | 文件头确认了格式 | 本项目构建出来的属于 Releases；构建要读的输入可以留 | 洁净 | 待审视 |

不检查的只有两类，名字都由放它们进来的工具规定：npm 的 `node_modules/`；`vendor/`（Go 规定的目录名，GitHub Linguist 的 vendor.yml 也认 `vendors?/`）；Go 的 `testdata/`（"The go tool will ignore a directory named "testdata""）；Jest、Vitest 写的 `__snapshots__/`；Linguist 认定的测试夹具 `tests/fixtures/`、`specs/fixtures/`。其他名字，chous 不猜，由仓库自己在 `.gitattributes` 里用 GitHub 的写法声明：`测试数据/** linguist-vendored`、`upstream/** linguist-vendored`，`linguist-generated` 同样生效，`-linguist-vendored` 把路径要回来。`tests/`、`examples/`、`playground/` 是你自己的代码，照常检查。
