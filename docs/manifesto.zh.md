# chous 宣言

> 能跑，但还是臭。

chous 检查一个仓库的品味：它整不整洁，有没有秩序，用的东西烂没烂。它不检查正确性、安全、性能、功能和测试。有 bug 的仓库可以很优雅，功能完全正确的仓库也可以很丑。

审美只有一套，不能配置、不能关闭。chous 有权指出丑陋，你有权保留丑陋。

## 四种品味

### 现代

- 停止维护的技术就是臭的，从停止维护那天起，没有宽限期。它还能跑，和臭不臭无关。
- 作者宣布废弃的、作者自己称为遗留（legacy）或维护模式的，都是臭的。
- 健康的旧技术不臭。不追新，不搞技术鄙视链：慢、老、不时髦都不算臭，没人宣布的「没人维护」也不算。

### 秩序

- 同一个东西只用一个名字，同一个目录只用一种起名方式。
- 根目录是入口，不是资料堆。
- 隐藏文件和普通文件同等对待：放在 `.` 开头的目录里，不会让一样东西变得不臭。
- 配置尽量集中，但不打破职责边界：一个工具的配置放一处，不同的工具各自一份。
- 不平铺，不堆积。一个目录里堆着几百个文件、一个文件塞进所有职责，都是没有组织。
- 同一个事实只说一遍。
- 用哪些工具、用几个，依赖多少，由你决定。

### 约定

- 语言规定了名字怎么写的，照规定来。官方说「没有定论」或「不做规定」的，chous 也不规定。
- 允许兼容多个运行时，允许必要的重复；说了两遍又不一致，才臭。
- 约定以官方原文为准。

### 洁净

- 不提交构建产物、系统垃圾、个人配置。
- 不保留工作留下的东西：手动备份、一次性脚本、某一次工作的记录。历史交给版本控制，过程交给 PR。
- 源码树里不放安装包，也不放大到不该进历史的文件。构建出来交给用户的东西，属于 Releases。
- 允许为未来扩展先建好空壳文件。空的不等于没用。

## chous 知道什么

chous 只说它确定的事实，所以每条结果分两种：

- **臭味**：事实明确，而且违反上面的品味，不需要再判断。
- **待审视**：事实明确，但它的含义需要 chous 没有的上下文。交给你或你的 agent 判断。

这两种不是严重程度，而是 chous 知道多少。没有错误、警告、提示之分，也没有分数。臭味会让 chous 以非零状态退出，待审视的不会。

**事实错了才是误报，审美不同不是。** 漏报可以接受，错误的事实不可以。知名项目也会妥协，chous 不为任何项目开例外；知名项目也不是审美标准。

## chous 不做什么

- 不惩罚缺失：没有测试、没有 CI、没有许可证，都不报。chous 只看你已经做了的选择。
- 行数、体积、文件数量不定性：超过 chous 的立场值，只让人去看。是否职责过度集中由 agent 判断，**不要机械拆分**。
- 不读名字里的词。换一种语言就要再猜一遍的规则，不是事实。只有工具或操作系统规定的确切名字算数，而且要有内容佐证。
- 不为迁就某个项目加豁免。
- 不收易变的知识。一条规则如果三年没人维护就不再成立，它就不该进来：除了停止维护和明确的废弃，需要知道具体软件的名字和版本才成立的规则，一概不收。
- 不联网，不调用 AI，不需要任何 key。

## 交给 agent 的部分

有些品味需要读懂代码才能判断，这些不写进 chous 的规则，由 agent 按这份宣言来判断：

- chous 列出的长文件是不是承担了太多职责。行数只是让人去看的理由，编译器的代码生成本来就大。**不要为了把行数压下来而机械地拆分文件**：一个职责一个文件，而不是一个行数一个文件。
- chous 列出的平铺目录，是不是应该按职责分组。
- chous 列出的重复文件，哪些是必要的（每种屏幕密度一份的图标），哪些是复制粘贴。
- 具体工具的配置是不是过时、放错了位置、被另一份覆盖：读工具最新的文档，或者运行它自己的诊断。
- 多种语言混用：一个职责用了两种语言实现，或者为了一点点功能引入一门新语言。
- 注释掉的旧实现：历史交给版本控制。
- 已经没有调用方的兼容层、适配层、转发层。
- 重复的实现、没有必要的抽象。
- 提交进来的生成代码，旁边却没有生成它的方法。
- 源码和文档里长期积累的派工记录、任务汇报、交付记录、按版本堆积的发布说明：事情做完了，来龙去脉在 PR 和 CHANGELOG 里，仓库里不必再留一份。agent 能读完，再决定哪些还要留。
- 一个文件到底还有没有用：工作日志、手动备份、一次性脚本、`plugin/` 和 `plugins/` 是不是一个东西。chous 不读名字里的词；agent 能读完它们，再决定该放进 docs/、写进 PR，还是删掉。

`chous manifesto` 会输出这份宣言，`chous --json` 会以结构化数据输出所有结果。agent 可以先读宣言，再结合结果审视整个仓库，而不只是处理 chous 列出的那几条。

具体查什么、立场值是多少、凭什么，见 [chous 的规则](rules.zh.md)。
